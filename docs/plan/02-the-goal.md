# The goal

There are eight claims. Each has a number or a predicate, each can turn out false, and each is checked by a command in `rucc-bsd` rather than by somebody reading a console log. They follow `rucc-kernel` 02, with the changes a whole operating system brings: a userland as well as a kernel, a build system with a knob for nearly everything, and a C++ compiler in the base.

Throughout this folder:
- **R** is the rucc build;
- **G** is the reference build of the same tree, with the same configuration, by the reference GCC of 04.3;
- **"G passes"** means a test passed in all three of G's baseline runs.

## 02.1 Unmodified

The source tree rucc builds is the pinned upstream commit, checked by hash before every build:
- **FreeBSD:** from `git.freebsd.org/src.git`.
- **NetBSD:** from `anonhg.netbsd.org` or its git mirror, pinned to the mirror's commit and the CVS date it records.
- **Releases:** the release's source distribution (FreeBSD's `src.txz`; NetBSD's `source/sets/` files `src.tgz`, `syssrc.tgz`, `sharesrc.tgz` and `gnusrc.tgz`), checked by SHA-256 against the project's signed checksum file.

Nothing is patched. No file is added to the tree, and nothing in it is regenerated by us. The build writes only under its object directories (`MAKEOBJDIRPREFIX`, or `build.sh -O` and `-T`).

Configuration is allowed. It is always one of the following, and every one of them applies identically to G.

**1. A toolchain description the system documents.**
- **FreeBSD:** a `CROSS_TOOLCHAIN` file in the format of the `devel/freebsd-gcc15` port's `xtoolchain.mk`, setting `XCC`, `XCXX`, `XCPP`, `X_COMPILER_TYPE` and `CROSS_BINUTILS_PREFIX`.
- **NetBSD:** the `TOOLDIR` that `build.sh tools` builds, where `bin/x86_64--netbsd-gcc` is the `rb-cc` shim (05.4). `bsd.own.mk:436` assigns `TOOL_CC.gcc` from `TOOLDIR`, so the shim is found by the build's own lookup.

The rucc description differs from G's in the C compiler line and nothing else. `rb toolchain-diff` checks this.

**2. Knobs in `src.conf` and `mk.conf`, from this list only:**

| System | Configuration | Knobs | Why |
|---|---|---|---|
| FreeBSD | `full` (weekly) | none (`SRCCONF=/dev/null`) | what FreeBSD's own GCC CI jobs build |
| FreeBSD | `graded` (nightly) | `WITHOUT_CLANG`, `WITHOUT_CLANG_BOOTSTRAP`, `WITHOUT_LLD`, `WITHOUT_LLD_BOOTSTRAP`, `WITHOUT_LLDB` | these remove LLVM, which is C++ only and built by `g++` in both R and G (10.3). They remove no C, and they are most of a world build's compile time |
| FreeBSD | `c-only` (10.5) | `graded`, plus `WITHOUT_GOOGLETEST` and `WITHOUT_PMC`, the knobs that remove C++ and little C. `WITHOUT_ZFS` would also remove `zfsd`, but it takes all of OpenZFS with it, so it is not used (10.5) | the row where rucc's share of objects is largest. It is graded but not the headline |
| NetBSD | `graded` (nightly and weekly) | none: NetBSD's defaults | GCC is the system's own compiler, built by `g++` in both R and G |
| NetBSD | `graded` on `riscv64` only | `MKCOMPAT=no` | the default builds `rv32` compatibility libraries (`compat/riscv64/rv32`), and rucc has no riscv32 back end. This removes an architecture outside the claim (02.6), in both R and G; it is not a workaround for a miscompile (11.3) |
| NetBSD | `c-only` (10.5) | `MKCXX=no` | a configuration NetBSD supports. It forces `MKATF`, `MKGCCCMDS`, `MKGDB`, `MKGROFF` and `MKKYUA` to `no` (`share/mk/bsd.own.mk:1674-1680`), so the row is tested with the `tests` set of the same pin's graded R build (10.5) |

Every line in a configuration file carries its reason in a comment. A knob turned off because rucc miscompiles what it controls is a patch by another name and is forbidden (14.1). In particular `WITHOUT_TESTS` and `MKATF=no` are never set, since the tests are the oracle. The one place `MKATF` becomes `no` is NetBSD's own forcing under `MKCXX=no`, and that row borrows its tests as 10.5 says.

**3. A kernel configuration the tree ships, or `RB-TEST`.**
- **FreeBSD:** `GENERIC`, `GENERIC-NODEBUG` and `MINIMAL`.
- **NetBSD:** `GENERIC`, and later `GENERIC_KASLR` and `MICROVM`.

`RB-TEST` (12.2) is a file of `include GENERIC` plus options the test rig needs, such as a serial console and the test kernel modules. It may only add options, and G uses it too.

**4. Make variables the build documents:**
- FreeBSD's `TARGET`, `TARGET_ARCH`, `KERNCONF`, `MAKEOBJDIRPREFIX`, `SRCCONF`, `__MAKE_CONF`, `CROSS_TOOLCHAIN` and `-j`;
- NetBSD's `build.sh` options `-m`, `-a`, `-O`, `-T`, `-U`, `-u`, `-j` and `-V MKREPRO=yes`.

Never allowed:
- a patch, including a `sed` over the tree;
- an extra `CFLAGS`, `COPTFLAGS`, `CWARNFLAGS`, `NOWERROR`, `NO_WERROR` or `WARNS` value;
- `TRY_GCC_BROKEN`, unless G uses it on the same row;
- a copied or regenerated file;
- an object built by anything other than the compiler the toolchain description names for it, apart from the two bring-up delegations of 00, which make a run ungraded.

## 02.2 Configured the same

Before any C is compiled, the build has asked the compiler many questions, and it configures itself by the answers. R and G must reach the same configuration. Configured the same means `rb mk-diff` (05.5) shows no difference beyond `mk-divergences.toml`, in each of these:
- **Every compiler-dependent make variable.**
  - FreeBSD: `COMPILER_TYPE`, `COMPILER_VERSION`, `COMPILER_FEATURES`, `COMPILER_FREEBSD_VERSION`, `LINKER_TYPE`, `LINKER_FEATURES`, and the X_ variants.
  - NetBSD: `ACTIVE_CC`, `HAVE_GCC`, `CC_WNO_*`, `MKGCC`, `MKLIBSTDCXX` and `HAVE_LIBGCC`.
- **The effective knob set.** These are FreeBSD's `make showconfig` and NetBSD's `make -V` of every `MK*` variable. A knob that depends on the compiler, such as FreeBSD marking `LIB32` broken for GCC on aarch64, must resolve the same way.
- **The kernel's option headers,** `opt_*.h` and `opt_global.h` on FreeBSD and `opt_*.h` on NetBSD.
- **The command line of every unit,** apart from the compiler's own path and the persona flag (05.6).

The divergence file exists for differences that are correct. An example is `COMPILER_RESOURCE_DIR`, which names each compiler's own directory. A difference caused by rucc answering a probe wrongly is a bug, never a divergence.

## 02.3 Passes

A row passes for one pin and one configuration when all of the following hold in one nightly run, on one rucc commit, with no bring-up flag.

**1. Builds.** The whole graded build succeeds:
- **FreeBSD:** `buildworld buildkernel`, then `installworld installkernel distribution` into a staging tree.
- **NetBSD:** `build.sh release`, or `distribution kernel=GENERIC` on rows where the release sets are not needed.

**2. Boots.** The disk image made from it (12.3) boots under QEMU on the row's machine to multi-user, and `rb-rc` reports in on the serial console.

**3. Smoke.** The smoke suite passes. It covers:
- `sh` and `csh`;
- the network up on `vtnet0` or `vioif0`;
- `fsck`, `mount` and `umount` of the root's sibling partition;
- `pkg` on FreeBSD and `pkg_add` on NetBSD;
- loading and unloading one kernel module;
- `/usr/tests` present.

**4. The system's own tests.** Every test case G passes, R passes:
- **FreeBSD:** `kyua test` over `/usr/tests`, counted by test case.
- **NetBSD:** `atf-run` and `atf-report` over `/usr/tests`, through the same rig.

A case G fails, skips or times out in any of its three runs is recorded and not graded. A case R passes and G fails is reported as a finding to look at, never as a credit.

**5. Clean kernel log.** R's console and `dmesg` show no panic, `KASSERT`, `WITNESS` lock order reversal, `INVARIANTS` failure, sanitizer report or `uvm_fault` that G's do not.

**6. Attribution.** Every failure is attributed by the 2x2 of 12.6:
- R kernel with G world;
- G kernel with R world.

A failure is filed against rucc only once the 2x2 says which half causes it.

## 02.4 All versions

"Latest" is what a user of each system would call latest today, plus whatever is still supported. Document 04 defines the sets. As of this writing:

| System | Current set, graded nightly | Releases set, graded weekly |
|---|---|---|
| FreeBSD | `main` (16.0-CURRENT), `stable/15`, `stable/14`, `releng/15.2` while in BETA and RC | 15.1-RELEASE, 14.5-RELEASE, 14.4-RELEASE until its end of life on 31 December 2026, and 15.2-RELEASE from 8 December 2026 |
| NetBSD | `trunk` (11.99), `netbsd-11`, `netbsd-10` | 11.1 and 10.2, and 11.0 until 11.1 has been graded for a month |

A new release joins the releases set the day it is tagged, and a branch leaves when the project ends its support. Releases older than the supported ones are outside the claim. The museum question, FreeBSD 2 to 4 and NetBSD 1.x built with GCC 2, is open question 11 and is not part of this goal.

## 02.5 Performance

**Runtime.** On amd64, the current FreeBSD and NetBSD releases are measured in a KVM guest on server3 with the benchmark set of 13.2:
- R's geometric mean is within 2% of G's;
- no benchmark is more than 5% behind;
- R's kernel text and libc text are within 5% of G's size.

This is the same gate as `rucc-kernel` K8, for the same reason. A base system is mostly branchy C that chases pointers and takes locks, and that is where a code generator shows.

**Compile time.** Over the C units of a `graded` world and GENERIC kernel, from the shim's records (13.4):
- the sum of rucc's user and system CPU time is at most half of the reference GCC's, at the same flags;
- no rucc process uses more than 1.5 GB.

"2x faster" is the rucc project's claim for itself. It is checked here on 30 million new lines of C, not assumed from Linux, where it stands at 1.75x on Linux 7.3 `defconfig` (rucc #4024).

Wall-clock time of the whole build is reported but not gated, because the C++ part (`g++`, which rucc does not touch) and `make` itself dominate it.

## 02.6 Architectures

| Row | Systems | Graded from | Notes |
|---|---|---|---|
| amd64 | FreeBSD, NetBSD | B3 | the first and the performance row |
| aarch64 | FreeBSD, NetBSD | B7 | QEMU `virt` with UEFI firmware, TCG on server1 and server2, KVM if a host is available |
| riscv64 | FreeBSD, NetBSD | B7 | NetBSD's riscv port is new in 11.0. Booted under QEMU TCG |
| i386 | NetBSD; FreeBSD `stable/14` only | B12 | FreeBSD 15.0 retired i386 as a platform, but 32-bit compatibility libraries on amd64 are graded from the first amd64 worlds (NetBSD `compat` at B4, FreeBSD `lib32` at B6), since they are i386 code built with `-m32` |

FreeBSD's armv7 and every powerpc variant are outside the claim. FreeBSD's own `Makefile.inc1` refuses a GCC build for them without `TRY_GCC_BROKEN`, so G does not exist there.

## 02.7 Systems

- **FreeBSD and NetBSD are the claim.** They are the two BSDs with a GCC build path that their projects maintain:
  - NetBSD's default compiler is GCC;
  - FreeBSD keeps GCC builds in CI and ships the cross GCC packages.
- **DragonFly BSD joins at B11.** Its base compiler is GCC 12.5 on master, it has a plug-in compiler mechanism (`CCVER` and `compilers.conf`), and it has one architecture. What it lacks is a test suite, so its claim is weaker: it builds, boots, passes smoke, and builds itself.
- **OpenBSD is not part of the claim** on any architecture that uses clang, which is all the ones in use. Its kernel and libc are built with OpenBSD-local clang options, such as `-fret-protector`, `-fret-clean` and `-ffixup-gadgets` (clang-local(1)). The GCC 4.2.1 architectures (alpha, hppa, m88k, sh) are legacy hardware. Document 04.2 and open question 3 hold the reasoning and what would change it.

## 02.8 What does not count

- **Objects built by the C++ compiler.** They count as G's code in R's system. `rb census` reports their share. The `c-only` rows exist to show that share can be made small.
- **The host tools,** until B12 (`bmake`, `nbmake`, `mkimg`, `makefs`, `config(8)` on the build host, NetBSD's host `nbgcc`).
- **Any run that used `RB_BRINGUP`.**
- **A rucc built from a dirty tree.**
- **Rows and configurations not listed above.** They may be built and reported, but they are not graded.
- **Third-party software from ports or pkgsrc built by rucc.** 12.8 only runs the project's own binary packages on R. Building ports with rucc is the job of `rucc-real-corpus` and of B10's system compiler row.
- **The claim of being faster than clang.** FreeBSD's own compiler is clang 21. Comparing against it is interesting and reported from B8, but the gate is the reference GCC, because that is what R and G share apart from the C compiler.
